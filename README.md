## 1. 目标

用尽量少的训练回答三个问题，再据此决定主线。

1. RLTT 的收益是否来自 `A > 0` 的 gap 项（跨 loop 蒸馏），`A < 0` 的 gap 项是否有害。
2. 把深度或 exit 当作策略的一部分并用 outcome reward 训练，能否在总计算量对准确率的前沿上胜过固定深度和现有 gate。
3. 在跨 loop 自蒸馏（RSI）上加 reward，是否有额外收益。前提是自蒸馏本身的增益能复现（H0）。

对应三个方案：方案 1（Sandwiched RLTT）、方案 2（Exit-marginal RL，分序列级 2a 和逐 token 2b）、方案 3（以更深的自己为参考的自蒸馏）。主线押方案 2，方案 1 作为诊断和消融。方案 3 原定保底，依据是 RSI 报告的增益；这个结果现在有争议（3.6 节），H0 通过之前不算保底。

## 2. 要检验的假设

| 编号 | 假设 | 什么结果算推翻 | 阶段 |
|---|---|---|---|
| H0 | D-LoopOPD（`ψ = 0`）在我们自己的评测下高于未训练的基座，差值超出重复评测的波动 | 差值落在波动之内 | 3 |
| H1 | RLTT 训练中，`A < 0` 样本上的平均 gap 上升，`A > 0` 样本上的下降 | 两者同向变化，或没有差别 | 1 |
| H2 | gap 系数从 `A` 改成 `max(A, 0)` 后，长预算准确率不低于 RLTT；系数取 0 时回答不再变短 | 系数 0 的臂同样变短，或 sandwich 更差 | 1 |
| H3 | loop 和 CoT token 互相替代：固定深度越浅，回答越长 | 回答长度与深度无关 | 0 |
| H4 | 每个要用的深度都需要带 reward 的 rollout；多深度 RL 后浅层准确率明显高于只在 4 个 loop 上做 RL | 单深度 RL 的浅层表现已经相当 | 2 |
| H5 | 深度由 reward 训练后，相同准确率下的总计算量低于固定深度（含扣同样计价的 GRPO@4）和现有 gate | 前沿没有外移 | 2、4 |
| H6 | reward-tilted 蒸馏在 over-looping 的题上优于纯 D-LoopOPD，整体不差于它 | 所有 `ψ > 0` 都不优于 `ψ = 0` | 3 |

## 4. 阶段 0：只测不训

目的：在花训练算力之前估计三个方案各自的空间，并验证评测脚手架。

先做一项校验：基座的准确率要能对上论文，对不上就先修脚手架。RSI 的 Vanilla 行不作为校验目标（3.6 节）。

- 逐深度：RLTT Table 9（MATH-500），Ouro Table 12 和 Table 13（AIME、OlympiadBench）。
- 4 个 loop：Ouro Table 9。AIME 的答案是整数，受判分方式影响小，作为主要校验点；2.6B-Thinking 的 AIME24 是 pass@1 64.7、pass@10 90.0，AIME25 是 50.3、76.7。OlympiadBench 在 Ouro 论文里用 LLM 判分，规则判分会偏低，只作参考。
- 生成长度上限要放够。RSI Table 6 里，基座的 AIME24 Avg@16 在 8K、16K、31K 上限下是 32.29、55.00、62.08。这些数字本身待核实，趋势可以参考：上限不够会直接量低基线。
- 基座重复评测若干次并记录波动，它是后面所有对比的噪声底。

| 编号 | 测什么 | 怎么算 | 决定什么 |
|---|---|---|---|
| M1 | gap 的集中程度 | 4 个 loop 的 rollout 上逐 token 算 gap，报告 gap 总量里前 1% 和前 5% token 的占比 | 方案 2b 的空间 |
| M2 | 答对与答错样本的 gap 差异 | 按 rollout 的对错分组比较平均 gap | 方案 1 是否值得做 |
| M3 | 逐 token 一致率 | loop 2、3 与 loop 4 的 top-1 一致的 token 比例 | 早退能省多少计算 |
| M4 | over-looping 比例 | 同一批题分别在固定 2、3、4 个 loop 下生成，统计浅层对而 4 个 loop 错的题，以及取并集的 oracle 准确率 | 方案 2a 的准确率空间，方案 3 是否需要 reward |

- M4 的 oracle 比固定 4 个 loop 高不到约 2 个点，且 M3 的一致率低：放弃方案 2，主线转方案 3。

## 5. 阶段 1：方案 1 与基线

目的：搭好训练管线，复现 GRPO 与 RLTT，检验 H1、H2。

目标函数统一写成 `A·log Σ_t ω_t P_t(y) − γ·gap`，各臂只差 `γ`。

| 臂 | `γ` | 含义 |
|---|---|---|
| GRPO | 不适用 | 只用 `log P₄(y)` |
| 精确项 | 0 | 只有混合似然，没有 gap 项 |
| RLTT | `A` | 论文原式 |
| Sandwich | `max(A, 0)` | 方案 1 |
| 常数 | 训练初期 `|A|` 的均值 | gap 项与 advantage 符号解耦 |

每步记录：reward、平均回答长度、最后一个 loop 的熵、`A > 0` 与 `A < 0` 样本上的平均 gap、各 loop 与 loop 4 的 top-1 一致率。

通过标准：见 H1、H2。评测按第 8 节。

## 6. 阶段 2：方案 2a，序列级的深度动作

目的：检验 H4、H5。这是方案 2 的第一版，rollout 是固定深度的静态图，节省的计算是真实的，不依赖早退推理。

做法：

- 每条 rollout 采一个深度 `k`，按固定深度生成。`k` 的候选集合由阶段 0 决定，默认 {2, 3, 4}。
- 策略梯度作用在 `log q(k|x) + log π^(k)(y|x)` 上，同一道题的一组 rollout 共用一个基线。
- return 里扣总计算量：`R − β·C`，`C = (Σ_j k_j) / (4 × 最大生成长度)`。`β` 的含义、取值和归一化见 6.1 节。

| 臂 | 深度怎么来 | `β` |
|---|---|---|
| GRPO@4 | 固定 4 | 0 |
| 多深度 | 在候选集合上均匀分层 | 0 |
| 多深度加计价 | 同上 | 扫 0.02、0.05、0.1、0.2 |
| 学习的深度先验 | `q(k|x)` 是 prompt 末位状态上的线性头，初始偏向 4 | 多深度加计价里最好的 |
| GRPO@4 加计价 | 固定 4 | 验证集选中的价格，以及对数距离最近的另一档 |

2026-11-21 执行修正：均匀分层采样的平均深度由采样设计固定在约 3，不能据此选择 β。四个正价格臂先按预先固定单价下的验证集效用选价（2/3/4 深度等权，平局取较低 β），学习深度头再使用选中的 β；测试集不参与选择。验证集为固定训练集留出 256 题，所有臂训练时排除。精确规则见 [native2a-plan.json](configs/native2a-plan.json)。

通过标准：多深度臂在 2、3 个 loop 下的准确率明显高于 GRPO@4 在同深度下的准确率（H4）；学习的深度先验那一臂的准确率对总计算量曲线在固定深度的各点之外（H5）。

### 6.1 计算价格取多少

阶段 2 和阶段 4 共用这一节。`β` 是唯一的旋钮，阶段 4 损失里的 `c = β / (4 × 最大生成长度)` 由它换算。

**含义。** `β` 是一条回答顶满最大长度、每个 token 都算满 4 个 loop 时扣掉的 reward（答对记 1）。也可以把它看成汇率：回答长度为 `L` 时，平均深度少 1 个 loop，return 多出 `β·L / (4 × 最大生成长度)`。训练出来的策略大致停在“再少算一个 loop 损失的准确率等于这个数”的位置。

最大生成长度取 2048 时：

| `β` | `c`（每个 loop-token） | 平均深度少 1 个 loop 值多少准确率（回答顶满长度） | 回答为一半长度时 |
|---|---|---|---|
| 0.02 | 2.4e-6 | 0.5 个点 | 0.25 个点 |
| 0.05 | 6.1e-6 | 1.25 个点 | 0.6 个点 |
| 0.1 | 1.2e-5 | 2.5 个点 | 1.25 个点 |
| 0.2 | 2.4e-5 | 5 个点 | 2.5 个点 |

对照 Mishra 等现有 gate 的前沿（Ouro-1.4B，第 4 节）：从 4 降到约 3.15 个 loop，每少一个 loop 约掉 1.8 个点；再降到约 2.5 个 loop，每少一个约掉 6 个点。所以 `β = 0.1` 大致落在平均深度 3 附近。训练会让前沿变平，同一个 `β` 下策略会走得比这更浅。这是粗估：140 步、学习率 1e-6 不一定训到最优，实际深度还取决于 gate 头的学习率。

**档位与升温。**

- 阶段 2 扫 0.02、0.05、0.1、0.2，先按上述验证集效用选价；β 与实际平均深度的关系需要在学习深度策略上测量。阶段 4 再依据其实际深度和验证表现确定档位。加 0.02 是因为浅层 KV 可能很伤（第 10 节风险 3），价格太高容易一下把 token 推得过浅。
- 每档都从 0 开始，在前 30% 的步数里线性升到目标值。30% 是暂定值。
- 换生成长度时固定 `c`，不固定 `β`。`c` 是每个 loop-token 的单价；最大生成长度从 2048 改到 4096 时 `β` 跟着翻倍，否则同一个 `β` 的单价减半。

**归一化。** 带计价的臂不能除组内标准差。组里 8 条都答对时，return 是 `1 − β·C_i`，减均值后是 `−β·(C_i − C̄)`，组内标准差是 `β·std(C)`，相除后 `β` 正好约掉，计算量的信号被放大到和答对答错一样的量级。简单题上模型会被很强地推着省计算，`β` 取多少都一样。全错的组同理。原本这类组的标准差为 0，会被过滤掉；加了价格之后标准差不为 0，它们会进入训练。改为除以整个 batch 上 `R` 的标准差 `σ_R`，这类组的信号只有 `β·(C_i − C̄) / σ_R`，`β` 保持汇率的含义。阶段 4 的价格项除以同一个 `σ_R`。另一个可选做法是不除标准差（Dr. GRPO），代价是学习率要重扫。

**长度惩罚的对照。** 价格按 `Σ_j k_j`（阶段 4 是 `Σ_j e_j`）算，回答越长扣得越多，所以 `β > 0` 本身带长度惩罚。只和 `β = 0` 的 GRPO@4 比，前沿外移可能只是回答变短了。GRPO@4 加计价固定 4 个 loop，价格是 `β·L / 最大生成长度`，等于纯长度惩罚；它和多深度加计价在同一个 `β` 下比，差值才是自适应深度的贡献。阶段 4 复用这个对照，前提是 `β` 取同样的档位。

## 7. 阶段 3：方案 3

目的：先检验 H0，再检验 H6。可与阶段 2 并行。

损失：`KL(P₂ ‖ sg P₄) − ψ·A·log P₂(y)`，rollout 来自 loop 2。

先跑 `ψ = 0` 一臂，与基座比较（H0）。RSI 报告它在 2.6B 的 AIME24 Avg@16 上比基座高 9.6 个点，公开评论称复现不出差别（3.6 节）。这一臂跑两个训练种子，评测按第 9 节重复。H0 不成立时，H6 的对照改为基座和 GRPO@2，问题变成 reward 能否让跨 loop 蒸馏起作用，是否继续投入另行决定。

| 臂 | `ψ` | 备注 |
|---|---|---|
| D-LoopOPD | 0 | 复现 RSI，同时检验 H0 |
| reward-tilted | 两到三档 | 先量 KL 项与 reward 项的梯度范数，取使两者同量级的值及其上下各一档 |
| GRPO@2 | 只有 reward 项 | 去掉 KL |

通过标准：见 H6。另外报告各臂在 2、3、4 个 loop 下的准确率，看浅层的收益是否带到深层。

## 8. 阶段 4：方案 2b，逐 token 的 exit

前提：阶段 0 的 M1、M3 显示有空间，且阶段 2 的结果为正。

rollout、update 和部署用同一个早退过程。早先的写法是训练时每个位置算满 4 个 loop，只在部署时早退；训练和部署因此是两个策略，这个写法已删除。

### 8.1 策略

- 位置 j 逐 loop 执行。算完第 t 个 loop，以 `λ_t` 的概率退出，并从 `P_t` 采样 token；否则继续，第 4 个 loop 必退。等价的说法是退出深度 `e_j ~ q`，`q_t = λ_t·Π_{s<t}(1−λ_s)`，`q_4` 取剩余质量。gate 用 Ouro 原生的逐 loop 形式，不用 softmax：softmax 要四个 logit 一起归一化，不能逐 loop 判定。
- 退出的 token 只留下 loop 1 到 `e_j` 的 KV。后面的 token 在 loop s 读它在 loop `min(s, e_j)` 的 KV，即 Ragged KV 的规则。continuous depth batching 的 last-exited 布局与它语义相同；shared cache 读到的是最近一次写入的状态，语义不同，不用。
- prompt 算满 4 个 loop（Mishra 等的 Dense 模式）。
- 这三条在 rollout、update、部署里完全相同。部署改用 Q-exit 阈值、换补位规则，或者引擎让退出延迟生效（continuous depth batching 里第 r 步的退出信号到第 r+2 步才生效），都是另一个策略。要用这样的引擎，训练就按它的规则来。
- 记 `s_j` 为位置 j 看到的历史：前面的 token，以及每个 token 到各自退出深度为止的 KV。`π_mix(y|s_j) = Σ_t q_t P_t(y)`，`ρ_t ∝ q_t P_t(y_j)`。

### 8.2 rollout 与 update

- rollout 按 8.1 生成，记录每个 token 的 `y_j` 和 `e_j`。优先用真实早退的推理实现，这时 rollout 的计算量是 `Σ_j e_j` 个 loop-token。没有实现时用静态图模拟（3.5 节）。
- update 做一次 ragged teacher forcing：4 个 loop 的静态图，注意力按记录的 `e` 取 KV。每个位置都把 4 个 loop 算完，得到四个读出和四个 gate 值。超出 `e_j` 的 loop 只用来算 `π_mix` 和 `ρ`，后面的位置读不到。位置 j 继续算深层时读自己的深层 KV，别的位置读它时按补位规则，两种读法要分开实现。update 不省 loop，成本与 RLTT 相同。
- 梯度穿过被复用的 KV 回传，不截断。
- PPO 需要的旧 log 概率由 update 一侧的同一种前向算出，不求导。rollout 引擎不算退出之后的 loop，给不出 `π_mix`。
- 开工前先验一件事：对同一条 rollout，update 一侧算出的 `log q_{e_j} + log P_{e_j}(y_j)` 要与 rollout 引擎返回的逐 token log 概率对上。对不上就说明两边不是同一个策略。

### 8.3 损失

每个生成位置的损失是

`−A_j·[ log π_mix(y_j|s_j) + κ·log ρ(e_j|s_j, y_j) ] + (β / (4 × 最大生成长度))·Σ_t t·q_t(s_j)`

- 方括号里的两项各自按 PPO 的方式做比值和裁剪。
- `κ = 1` 时 `log π_mix + log ρ = log q_{e_j} P_{e_j}(y_j)`，是联合动作（退出深度和 token）的 log 概率，整个损失给出 8.1 那个策略的精确策略梯度。
- 第一项对本位置的退出深度求了和，方差低，管的是信哪个 loop 的读出。reward 经它落到 gate logit `a_t` 上的梯度是 `ρ_{≥t}·(ρ_t/ρ_{≥t} − λ_t)`，`ρ_{≥t} = Σ_{s≥t} ρ_s`，四个 loop 一致的 token 上为 0。
- 第二项是校正项，管的是早退让后面的 token 少看了什么。只有当回报在给定 token 之后还依赖退出深度时，它的期望才不为零。`κ = 0` 去掉它，方差更低但有偏：gate 的退出决定拿不到早退伤到后文的信号，只有表示会经 KV 的梯度去适应。
- 第三项是本位置期望深度的可导惩罚。一致的 token 上 gate 靠它学早退。系数 `β / (4 × 最大生成长度)` 就是 `c`，取值见 6.1 节。
- `A_j` 的 return 是 `R − β·C_{−j}`，`C_{−j}` 是其余位置的退出深度之和除以 `4 × 最大生成长度`。本位置的深度已经由第三项精确计入，再放进 return 会重复计算。baseline 用同一道题组内 `R − β·C` 的均值，再除以整个 batch 上 `R` 的标准差 `σ_R`，第三项除以同一个数。不能除组内标准差，原因见 6.1 节。
- 分解和 gate 梯度用可穷举的小过程核对过（`python scripts/exit_marginal_check.py`，只依赖 torch）。校正项在 Ouro 上有多大未知，M7 量的是它的来源。

### 8.4 起步与臂

- gate 的 logit 统一减一个常数，使初始平均深度接近 4。这时几乎每个 token 都退在 loop 4，训练从接近 GRPO 的状态开始。不能直接按 Ouro 原生的 `q` 采样：它是给 Q-exit 阈值用的，没有被当作采样分布用过；Mishra 等说它在各 token 上熵都高，按它采样很可能有不少 token 退在很浅的 loop。常数也不能大到让 sigmoid 饱和，否则 gate 拿不到梯度。
- `β` 从 0 开始，在前 30% 的步数里线性升到目标值。目标值取阶段 2 里平均深度落在 2.5 到 3.5 之间的两档（6.1 节）。
- gate 头的学习率单独设。3.3 节的 1e-6 是给 LM 权重的，gate 头多半要更大，待扫。
- 3.3 节的 KL 正则在这里是否保留、对哪个分布，待定。

| 臂 | `κ` | 用途 |
|---|---|---|
| 精确 | 1 | 主臂 |
| 只有混合项 | 0 | 消融：方差换偏差是否值得 |

一次训练只给出一个工作点，由 `β` 决定。部署时再调阈值换工作点，得到的不是训练过的策略；要画前沿就训练多个 `β`。

Mishra 等第 5 节有 ragged-aware 的训练（非 RL），原文和数字还没有读，开工前补读。

### 8.5 评测

按 8.1 的策略生成，准确率和 loop-token 数都取自这个模式，H5 只看它。固定 1 到 4 个 loop 的结果按第 9 节照常报告，作参照。

第 4 节里 Mishra 等的数字量自现有的 gate。他们的解释是相邻 token 的退出深度很少跳变，而 2b 训练出来的 `q` 要随 token 变化，所以那组数字不能当作 2b 的效果估计。训练中持续记录平均深度、退出深度的分布、相邻 token 的跳变率和 M7。

## 9. 评测协议（所有阶段通用）

- **按总计算量对齐。** 报告准确率对 loop-token 数（每个 token 用的 loop 数之和），不只报告 token 预算下的准确率。逐 token 早退的模型，准确率和 loop-token 数都取自动态早退模式（8.5 节）。
- **多个解码预算。** 1024、2048、4096，再加一个不设限的档。主结论看长预算。AIME 类的题不设限档要到 31K 左右，上限不够会量低所有模型（见第 4 节的校验）。
- **采样评测。** 用 Avg@16 一类的多次采样加配对检验，温度沿用所复现论文的设置，在阶段 0 定下来。
- **报告波动。** 每个数字给出重复评测的均值和标准差。AIME 每套 30 题，一题是 3.33 个点，结论以 Avg@k 为准，Pass@k 只作参考。H0 的 D-LoopOPD 臂跑两个训练种子，其余对比的种子数看到阶段 0 的波动后再定。
- **基线同批评测。** 未训练的基座与每个训练臂用同一脚手架、同一设置、同一批次评测，保留逐样本日志。不拿别的论文里的基座数字做对比。
- **逐深度。** 每个模型都在 1 到 4 个 loop 下评测。
- **数据集。** MATH-500、AIME24、GSM8K、BeyondAIME；迁移看 GPQA 和 MBPP。
- **可监控性。** 至少报告 reasoning token 数。有余力时加一个 monitor 指标，因为方案 2 和方案 3 都会把推理从可见 token 挪进 loop。

## 10. 风险

1. **基线偏弱或被量低。** RLTT 论文里 GRPO 的 reward 曲线几乎不动。RSI Table 2 里 RLTT 低于未训练的模型，但那张表的 Vanilla 行有争议（3.6 节），只能当线索。GRPO 的学习率要单独扫，各臂要比较更新范数，否则结论可能只是有效步长的差别。未训练的基座同样要量准，RSI 的争议就出在这一步。
2. **reward 在 Ouro 上可能提不了多少准确率。** Ouro 论文 4.5 节说自己的 RL 尝试没有明显超过 SFT checkpoint。RSI Table 2 里 GRPO 只比 Vanilla 高 0.8 个点，这个差值依赖有争议的 Vanilla 行。方案 2 的评价因此以计算量前沿为主。
3. **方案 2b 的一致性靠实现保证，早退本身也可能掉点。** rollout、update、部署要用同一套退出规则、补位规则和 prompt 处理（8.1 节），update 的 ragged 重算还要和 rollout 引擎对得上（8.2 节的核对）。Ragged KV 不经训练就能用的结果量自现有的 gate，2b 训练后退出深度的跳变会变多。Ouro 论文 Table 14 里，只用 loop 1 的 KV 顶替全部深度时 GSM8K 从 78.92 掉到 18.73。校正项的方差也未知。对策是 M7、起步时偏向 loop 4，以及 `κ` 的消融。
4. **简单阈值可能已经够好。** M6 就是为了提前看到这一点。
5. **被抢先。** 方案 3 离 RSI 最近。阶段 3 与阶段 2 并行，不排在最后。
6. **方案 3 的前提可能不成立。** 方案 3 假设不用 reward 的跨 loop 蒸馏已经有增益，reward 是在它之上的修正。H0 不成立时，方案 3 没有可靠的 `ψ = 0` 起点。对策见阶段 3。
